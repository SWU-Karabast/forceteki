# SWU-PGN 1.0 spec review — possible plan

**Status:** proposed, not started. Waiting on SWUForge's review of the spec before deciding
scope. Nothing here has been applied.
**Spec:** `docs/SWU-PGN-1.0-SPEC.md` at `ad8c0fef1` (branch `swu-game-notation`, PR #2350).
**Date:** 2026-10-27.

## How this was reviewed

- A mechanical pass: every internal link, file path, `§` reference and quoted JSON record.
- An accuracy audit: every normative statement checked against `swupgn/src`, the schemas, the
  writer (`server/game/core/chat/SwuPgn*.ts`) and all 8 vectors, with the compiled reader run
  over each vector.
- A standards-grade editorial review (conformance, grammar, versioning, security, privacy,
  media type, structure).
- A speed pass on the reader and on file size.
- The top findings of each reviewer were spot-checked against the files before being recorded.

**Baseline:** the code and vectors agree with each other. All 8 vectors parse, validate with 0
issues, match their `.fold.json` / `.render.txt` byte for byte, pass `checkKeyframes` with 0
mismatches, and embed a STORY equal to `render()`. Every problem in Sections 1-3 is in the
document. Section 5 adds reader bugs found later (two from swoostory, three from a
real-game audit), which the vectors do not cover.

## Section 2 — Contract changes for a public 1.0 (decisions)

1. **Make the text normative.** §2 (l.72-74) says "when this document and the code disagree,
   the code in `swupgn/` wins". Reverse it: the text is normative, vectors are its conformance
   suite, the reference code is informative, and a disagreement is an erratum.
2. **Define document conformance levels.** Today §14 lets a writer ship a file that fails
   `checkKeyframes`, §20 says every conformant file has zero mismatches, and §3's ~45 writer
   MUSTs are mostly untestable. Proposed:
   - **well-formed:** parses per the grammar;
   - **valid:** schemas plus cross-record rules (unique `seq`; every `for` / `ref` / `at`
     resolves; zone vocabulary; `from ≠ to`) — `validate.ts` checks none of the cross-record
     rules today;
   - **verified:** zero keyframe mismatches;
   - **complete:** no `RecorderErrors`, no `DEFEAT.reason: "unknown"`.

   Say which level each conformance class produces or must accept.
3. **Renderer: strict vs structural.** §3 (l.185-186) and §16 (l.2310-2312) say "MUST produce
   exactly these lines"; §16 (l.2446) says the wording is advisory. Split into a *strict
   renderer* (byte-identical to the vectors, used to verify STORY) and a *renderer* bound only
   to the structural rules (l.2454-2456). Pin what strict needs: the `{names}` join, the
   banner's trailing space, overflow past 78 columns, the trailing newline.
4. **Versioning holes** (before the first 1.1):
   - `DECKS` is `additionalProperties: false`, so no minor version can add a deck field;
   - closed vocabularies (`DEFEAT.reason`, …): a reader of a higher-minor file MUST downgrade
     out-of-vocabulary values to warnings, or 1.0 validators reject 1.1 files;
   - a minor version MUST NOT add an event whose omission changes an existing `ReducedState`
     field (new state goes in new fields, compared only by readers that know them);
   - changing the zone vocabulary, seq grammar, card-id grammar or seat values is MAJOR;
   - say what readers do with unknown fields inside keyframes, and whether to warn on a higher
     minor;
   - reserve an extension prefix (`X_` event types, `x-` fields, `X` tags) readers MUST ignore.
5. **Pilot files and `WriterRevision`:**
   - a file with no `WriterRevision` is pre-release, not SWU-PGN/1.0 conformant; the §22 Detect
     table moves to an informative "Reading pre-release files" appendix;
   - fix §22's "no earlier file in the wild" (contradicts the pilot paragraph after it);
   - scope `WriterRevision` to the product named by `Engine`'s prefix before `@`, so a
     SWUForge revision 1 and forceteki's do not collide;
   - after publication no meaning change may ride on `WriterRevision`; it is diagnostic only.
6. **Security Considerations** (new section):
   - resource limits: a reader MAY cap file size, line length and record count, and MUST reject
     rather than truncate;
   - keys from the file (`statusTokens`, `players`, keyframe maps) MUST NOT be treated as
     prototype-bearing (`__proto__`, `constructor`);
   - numeric overflow on `amt` / `count`, and JSON nesting depth;
   - display injection: `CARDS.name`, `Reason`, `CHOICE.prompt`, `title` and annotation `text`
     are attacker-controlled — escape for display, and neutralise bidi and control characters;
   - integrity is not authenticity: a verified file proves internal consistency, not that the
     game happened;
   - **an omniscient file MUST NOT reach a participant before the match ends** (it carries both
     decklists and sideboards, deck order and seed). The server already enforces this
     (`Lobby.ts` `getGameLog`: `isMatchOver()`), but the spec never states it.
7. **Privacy Considerations** (expand §17): deck lists are a cross-game fingerprint that defeats
   the per-game salt; constrain `GameId` like `Match` (no host-internal ids); annotation text is
   the annotator's responsibility; keyed-HMAC ids are still pseudonymous personal data; move the
   `ms` fingerprint note here from §5.2.1.
8. **Card identifiers: normative reference.** Name the data source and version that assigns set
   codes and numbers, the zero-padding and case rules, how variant printings map, and where a
   token's numeric id comes from. Add a set-code table.
9. **Front matter:** Abstract; Status of This Document (date, state such as "Candidate
   Recommendation, pilot", feedback channel, path to final); license (e.g. CC-BY-4.0 for the
   text, MIT or CC0 for schemas and vectors); trademark disclaimer; make the schema `$id`s
   (`https://karabast.net/swu-pgn/1.0/...`) resolve or switch them to URNs.
10. **Grammar:** an ABNF appendix (RFC 5234) for the file, header line, tag value and escapes,
    banner, `seq`, card id, `base@N` and `sha256:<hex>`. State: records are I-JSON (RFC 7493);
    events are processed in file order (today it is advice, l.671); writers MUST NOT emit a
    BOM and readers SHOULD strip one; the first line MUST be `[Game "SWU-PGN/…"]`. Settle text
    outside `[...]`, unknown escapes (`\n` currently becomes `n`), duplicate banners and the
    final newline.
11. **Spec ↔ schema drift:** `Rounds` is "a string of digits" in §5.1 but `integer` in the
    schema, and `[Rounds "seven"]` parses to `0` and validates clean; `Game` is "Exactly
    `SWU-PGN/1.0`" in §5.1 but `1.\d+` in the schema and §18.
12. **`INIT` seq: `R1.S.0` → `R0.S.0`.** Every other setup record is `R0.S.*`; the spec documents
    the mismatch as "Odd but true" (l.662, 670). Cheap now (one writer change, regenerate the
    vectors, pilot files go in the pre-release appendix); a breaking change after publication.
    **Pending: what SWUForge says.**

  (l.387, 671, 1430, 1646, 1688, 2105, 2146, 2272, 2301-2303, 2553-2554, 2820; "No other fields
  are allowed" at l.646 and l.2278).
- Replace function-named MUSTs ("MUST run `checkKeyframes()`", "before the engine cleans up")
  with observable file properties; move implementation advice to a "Reference writer notes"
  appendix.
- Give each normative statement an id (e.g. `[W-MOVE-3]`) and make §3 an index per class; add
  Parser/Consumer and Validator classes; define the `.fold.json` comparison (deep JSON equality,
  key order insignificant, array order significant, absent ≠ `null`).
- One normative home for fold semantics (§12); §10 field tables normative for syntax only; the
  §10.3/§10.4 "A reader handles … if" checklists become informative.
- Publish `ReducedState` as JSON Schema (`$defs/keyframe` already exists) with its
  serialization rules.
- Header value formats: RFC 3339 profile for `Date` / `EndDate`; `P1Id` / `P2Id` as `sha256:`
  + 64 lowercase hex (Appendix A's `sha256:aaaa` would then need fixing); case sensitivity of
  `Result` / `Perspective`; `Reason` and `Format` as open, registered vocabularies; `CardPool`
  grammar; `Rounds` for an incomplete game.
- Normative references (RFC 2119/8174, 8259, 7493, 3339, 5234, 3629, JSON Schema 2020-12,
  FIPS 180-4, RFC 2104) and informative ones (PGN, JSON Lines, the Comprehensive Rules pinned
  to one version — §11 cites v8.0 while the repo's rules reference is v7.0).
- One error model table: condition → fatal / record skipped / warning, with error codes rather
  than normative message strings; decide whether one bad JSON line aborts the whole file.
- Registries (one file, with a change process): event types, header tags, sections, zones,
  reserved token names, `DEFEAT.reason`, `damageType`, ability `kind`, NAG glyphs, set codes.
- Media type: a full IANA template (consider `text/vnd.karabast.swu-pgn`), `charset`, the first
  line as magic number, and `#R2.A.3` seq fragment identifiers for replay deep links.
- Perspective files are underspecified: how hidden `MOVE`s and `DRAW.cards` are written and how
  the fold stays consistent.
- `GAME_END.winner` mixes `1 | 2 | "Draw"`; consider aligning with `Result`.
- **Negative vectors** that readers MUST reject or warn on: unknown section, unknown `t`,
  damaged keyframe, bad `MOVE`, `__proto__` token, over-cap list, higher minor version. Package
  the vectors with a manifest (input, expected output, conformance class, pass criterion).
- Nice to have: terminology section; keep the plain-English voice in informative "In plain
  words" call-outs with the normative sentence first; i18n note (`CARDS.name` English, NFC);
  ASCII fallback note for STORY's box-drawing glyphs; acknowledgements (SWUForge, Karabuddy);
  formal section titles with the friendly subtitle.

## Section 4 — Speed: no change needed

Measured on the reference reader, averaged over 200 runs:

| Vector | Size | Events | parse | validate | fold | check | render | scrub to every seq |
|---|---|---|---|---|---|---|---|---|
| death-star | 62 KB | 306 | 0.19 ms | 0.37 ms | 0.13 ms | 0.21 ms | 0.09 ms | 2.0 ms |
| homeworlds | 52 KB | 304 | 0.17 ms | 0.32 ms | 0.09 ms | 0.12 ms | 0.06 ms | 1.9 ms |

- Keyframes are 27–41% of a file, and each `ROUND_START` keyframe repeats the previous
  `ROUND_END` except `round` / `phase` / `active` / `initiativeTaken`. Gzip brings a game to
  ~6 KB, and the socket.io download is already compressed (`GameServer.ts:456`,
  `perMessageDeflate`). Keep the keyframes: they are the scrub and recovery anchors.
- Possible addition: one sentence telling hosts to serve `.swupgn` compressed.
